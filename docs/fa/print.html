آموزش جامع Rust (راست) به زبان فارسی

مقدمه: Rust چیست و چرا باید یادش گرفت؟

به آموزش جامع Rust (راست) به زبان فارسی خوش آمدید. این کتاب رایگان و متن‌باز است و هدفش این است که فقط با خواندن آن، از صفر تا سطح یک برنامه‌نویس Rust مسلط پیش بروید.

Rust چیست؟

Rust یک زبان برنامه‌نویسی سیستمی، سریع و ایمن است. این زبان در سال ۲۰۰۶ به‌عنوان پروژه شخصی گریدون هور (Graydon Hoare) شروع شد، بعدها موزیلا از آن حمایت کرد و نسخه ۱.۰ آن در سال ۲۰۱۵ منتشر شد. امروز Rust توسط بنیاد Rust (Rust Foundation) و جامعه‌ای بزرگ از توسعه‌دهندگان نگهداری می‌شود.

سه ویژگی اصلی Rust این‌هاست:

  1. سرعت: Rust به کد ماشین کامپایل می‌شود و سرعتی در حد C و C++ دارد. Garbage Collector ندارد.
  2. ایمنی حافظه: بیشتر خطاهای رایج حافظه (مثل دسترسی به حافظه آزادشده، data race و null pointer) در زمان کامپایل گرفته می‌شوند، نه زمان اجرا.
  3. ابزار عالی: ابزارهایی مثل cargo (مدیریت پروژه و پکیج)، rustfmt (فرمت کد) و clippy (راهنمای کد بهتر) همراه خود زبان می‌آیند.

Rust را کجا می‌بینیم؟

Rust در حوزه‌های زیر کاربرد زیادی دارد:

  • سیستم‌عامل و زیرساخت: بخش‌هایی از هسته لینوکس، اندروید و ویندوز با Rust نوشته می‌شوند.
  • وب‌سرور و بک‌اند: با فریم‌ورک‌هایی مثل Axum و Actix.
  • ابزارهای خط فرمان: مثل ripgrep، bat و fd.
  • WebAssembly: اجرای کد سریع در مرورگر.
  • بازی‌سازی و گرافیک: مثل موتور Bevy.
  • سیستم‌های نهفته (Embedded) و بلاکچین.

چرا یادگیری Rust ارزش دارد؟

  • سال‌های متوالی در نظرسنجی Stack Overflow پرطرفدارترین زبان بین توسعه‌دهندگان شناخته شده است.
  • یادگیری آن شما را مجبور می‌کند درباره حافظه، مالکیت داده‌ها و همزمانی عمیق‌تر فکر کنید. این دانش در هر زبان دیگری هم به کارتان می‌آید.
  • بازار کار Rust در حال رشد است و شرکت‌های زیادی به دنبال برنامه‌نویس Rust هستند.

Rust سخت است؟

صادقانه بگوییم: شیب یادگیری Rust از بیشتر زبان‌ها تندتر است. دلیلش مفاهیمی مثل Ownership و Lifetime است که در زبان‌های دیگر وجود ندارد. اما خبر خوب این است:

  • کامپایلر Rust پیغام‌های خطای بسیار دقیق و راهگشا می‌دهد.
  • وقتی این مفاهیم جا بیفتند، کد نوشتن در Rust لذت‌بخش و مطمئن می‌شود.
  • این کتاب مفاهیم را قدم‌به‌قدم و با مثال توضیح می‌دهد.

این کتاب برای چه کسی است؟

  • کسی که تازه برنامه‌نویسی را شروع کرده و Rust را به‌عنوان اولین زبانش انتخاب کرده است.
  • برنامه‌نویسانی که با پایتون، جاوااسکریپت، جاوا، C++ یا Go کار کرده‌اند و می‌خواهند Rust یاد بگیرند.

پیش‌نیاز خاصی لازم نیست. فقط اگر با ترمینال (خط فرمان) آشنا باشید، کارتان راحت‌تر است.

نصب Rust روی ویندوز، مک و لینوکس

ابزار رسمی نصب و مدیریت نسخه‌های Rust، برنامه‌ای به نام rustup است. با نصب آن، این‌ها نصب می‌شوند:

  • rustc: کامپایلر Rust
  • cargo: ابزار ساخت پروژه و مدیریت پکیج
  • rustup: برای به‌روزرسانی و تغییر نسخه

لینوکس و مک

ترمینال را باز کنید و این دستور را اجرا کنید:

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

گزینه‌ی پیش‌فرض (1) را انتخاب کنید. پس از پایان، ترمینال را ببندید و دوباره باز کنید.

برای کامپایل کردن، به یک لینکر (linker) هم نیاز است:

  • مک: دستور xcode-select --install
  • اوبونتو و دبیان: دستور sudo apt install build-essential

ویندوز

  1. به سایت رسمی rust-lang.org/tools/install بروید.
  2. فایل rustup-init.exe را دانلود و اجرا کنید.
  3. اگر از شما خواست Visual Studio C++ Build Tools را نصب کنید، موافقت کنید. بدون آن، لینک کردن برنامه کار نمی‌کند.
  4. گزینه‌ی پیش‌فرض را بزنید و صبر کنید.

نکته: اگر دسترسی به سایت‌ها محدود است، می‌توانید از میرورهای rustup استفاده کنید. برای این کار، متغیرهای RUSTUP_DIST_SERVER و RUSTUP_UPDATE_ROOT را به آدرس میرور مورد نظر تنظیم کنید.

Hello World و آشنایی با Cargo

اولین برنامه

یک پوشه بسازید و فایلی به نام main.rs در آن ایجاد کنید:

fn main() {
    println!("سلام دنیا!");
}

با دستور rustc کامپایل و اجرا کنید:

rustc main.rs
./main          # در ویندوز: main.exe

خروجی:

سلام دنیا!

این کد چه می‌کند؟

  • fn main() تعریف یک تابع به نام main است. اجرای هر برنامه Rust از این تابع شروع می‌شود.
  • { ... } بدنه‌ی تابع را مشخص می‌کند.
  • println! یک macro است، نه تابع معمولی. علامت ! این را نشان می‌دهد. این macro متن را چاپ می‌کند و به خط بعد می‌رود.
  • هر دستور با ; تمام می‌شود.
  • تورفتگی (indent) در Rust با ۴ فاصله انجام می‌شود.

Cargo: ابزار اصلی Rust

در عمل تقریباً هیچ‌کس مستقیم از rustc استفاده نمی‌کند. Cargo کارهای زیر را انجام می‌دهد:

  • ساخت پروژه
  • کامپایل
  • دانلود و مدیریت کتابخانه‌ها (که در Rust به آن‌ها crate می‌گویند)
  • اجرای تست‌ها
  • ساخت مستندات

ساخت پروژه جدید

cargo new hello_rust
cd hello_rust

ساختار پروژه:

hello_rust/
├── Cargo.toml
└── src/
    └── main.rs

فایل Cargo.toml اطلاعات پروژه را نگه می‌دارد:

[package]
name = "hello_rust"
version = "0.1.0"
edition = "2024"

[dependencies]
  • بخش [package] نام، نسخه و edition را مشخص می‌کند.
  • بخش [dependencies] جایی است که کتابخانه‌های مورد نیاز را می‌نویسید.

دستورات مهم Cargo

دستورکاربرد

نکته: در حین نوشتن کد از cargo check زیاد استفاده کنید. چون فایل اجرایی نمی‌سازد، بسیار سریع‌تر از cargo build است.

حالت debug و release

  • cargo build فایل را در target/debug/ می‌سازد. زمان کامپایل کم است ولی برنامه کندتر اجرا می‌شود.
  • cargo build --release فایل را در target/release/ می‌سازد. کامپایل طولانی‌تر است ولی برنامه بسیار سریع‌تر اجرا می‌شود.

برای اندازه‌گیری سرعت و انتشار نهایی، همیشه از --release استفاده کنید.

اضافه کردن کتابخانه

مثلاً برای استفاده از کتابخانه تولید عدد تصادفی rand:

cargo add rand

این دستور خط مربوطه را در بخش [dependencies] می‌نویسد. کتابخانه‌ها از سایت crates.io دانلود می‌شوند.

فایل Cargo.lock

Cargo پس از اولین build فایل Cargo.lock را می‌سازد و نسخه دقیق همه‌ی وابستگی‌ها را در آن ثبت می‌کند تا build شما همیشه تکرارپذیر باشد. این فایل را دستی ویرایش نکنید.

تمرین

  1. با cargo new یک پروژه به نام my_first بسازید و آن را اجرا کنید.
  2. متن خروجی را به نام خودتان تغییر دهید.
  3. با println! سه خط مختلف چاپ کنید.
  4. دستور cargo build --release را اجرا کنید و محل فایل اجرایی را پیدا کنید.

فصل بعد: متغیرها و تغییرپذیری.

متغیرها، تغییرپذیری و ثابت‌ها

تعریف متغیر با let

در Rust متغیر با کلمه‌ی let تعریف می‌شود:

fn main() {
    let x = 5;
    println!("مقدار x برابر است با {x}");
}

داخل {} در println! می‌توانید مستقیم نام متغیر را بنویسید (این قابلیت format string است).

برای عبارت‌های پیچیده‌تر از {} خالی و آرگومان استفاده کنید:

fn main() {
    let a = 3;
    let b = 4;
    println!("جمع {} و {} برابر است با {}", a, b, a + b);
}

متغیرها به‌طور پیش‌فرض تغییرناپذیرند

این یکی از مهم‌ترین تفاوت‌های Rust با زبان‌های دیگر است. اگر مقدار یک متغیر را بخواهید عوض کنید:

fn main() {
    let x = 5;
    x = 6; // ✗ خطا: نمی‌توان به متغیر تغییرناپذیر دوباره مقدار داد
    println!("{x}");
}

کامپایلر خطای cannot assign twice to immutable variable می‌دهد.

چرا؟ چون وقتی بدانید مقداری تغییر نمی‌کند، فهمیدن و اشکال‌زدایی کد ساده‌تر است و بخش زیادی از باگ‌ها از بین می‌روند.

تغییرپذیری با mut

اگر واقعاً نیاز به تغییر دارید، کلمه‌ی mut (مخفف mutable) را اضافه کنید:

fn main() {
    let mut x = 5;
    println!("x = {x}");
    x = 6;
    println!("x = {x}");
}

خروجی:

x = 5
x = 6

قاعده کلی: فقط وقتی mut بگذارید که واقعاً لازم است. کامپایلر هم اگر mut غیرضروری بگذارید هشدار می‌دهد.

ثابت‌ها (const)

ثابت‌ها همیشه تغییرناپذیرند و تفاوت‌هایی با let دارند:

  • با const تعریف می‌شوند و نوع آن‌ها باید نوشته شود.
  • نمی‌توان mut به آن‌ها داد.
  • مقدارشان باید در زمان کامپایل مشخص باشد.
  • می‌توانند در هر scope از جمله سطح بیرونی فایل تعریف شوند.
  • نام‌گذاری آن‌ها با حروف بزرگ و _ است.
const MAX_POINTS: u32 = 100_000;
const SECONDS_IN_HOUR: u32 = 60 * 60;

fn main() {
    println!("{MAX_POINTS} {SECONDS_IN_HOUR}");
}

نکته: در اعداد بزرگ می‌توانید برای خوانایی از _ استفاده کنید: 1_000_000.

Shadowing (سایه‌اندازی)

می‌توانید متغیری با همان نام دوباره با let تعریف کنید. متغیر جدید متغیر قبلی را "سایه‌اندازی" می‌کند:

fn main() {
    let x = 5;
    let x = x + 1;

    {
        let x = x * 2;
        println!("x داخل بلوک: {x}"); // 12
    }

    println!("x بیرون بلوک: {x}"); // 6
}

تفاوت shadowing با mut

۱. در shadowing یک متغیر کاملاً جدید ساخته می‌شود، بنابراین می‌توانید نوع را هم عوض کنید:

fn main() {
    let spaces = "   ";         // نوع: &str
    let spaces = spaces.len();  // نوع: usize
    println!("{spaces}");
}

۲. اگر همین کار را با mut انجام دهید، خطای نوع می‌گیرید:

fn main() {
    let mut spaces = "   ";
    spaces = spaces.len(); // ✗ خطا: نوع‌ها یکسان نیستند
}

۳. بعد از shadowing، متغیر جدید هم همچنان تغییرناپذیر است مگر خودتان mut بگذارید.

Scope (حوزه)

متغیر از جایی که تعریف شده تا انتهای بلوک { } که در آن قرار دارد معتبر است:

fn main() {
    {
        let inner = 10;
        println!("{inner}");
    } // اینجا inner از بین می‌رود

    // println!("{inner}"); // ✗ خطا: inner دیگر وجود ندارد
}

این مفهوم در فصل Ownership نقش کلیدی دارد.

تمرین

  1. متغیری با let تعریف کنید و سعی کنید مقدارش را عوض کنید. خطا را بخوانید.
  2. آن را با mut درست کنید.
  3. یک const برای عدد پی (3.14159) تعریف کنید و مساحت دایره‌ای با شعاع ۵ را چاپ کنید.
  4. با shadowing، یک متغیر رشته‌ای را به عدد تبدیل کنید (راهنمایی: "42".parse::<i32>().unwrap()).

فصل بعد: انواع داده.

انواع داده در Rust

Rust یک زبان با نوع‌دهی ایستا (statically typed) است؛ یعنی نوع همه‌ی متغیرها باید در زمان کامپایل مشخص باشد. در بیشتر موارد کامپایلر خودش نوع را حدس می‌زند (type inference)، اما گاهی باید صریح بنویسید:

fn main() {
    let guess: u32 = "42".parse().expect("این یک عدد نیست!");
    println!("{guess}");
}

بدون : u32 کامپایلر نمی‌داند parse را به چه نوعی تبدیل کند.

انواع داده در Rust دو دسته‌اند: اسکالر (یک مقدار) و مرکب (چند مقدار).

انواع اسکالر

اعداد صحیح (Integer)

بسته به معماریisizeusize
  • i یعنی signed (می‌تواند منفی باشد)، u یعنی unsigned (فقط صفر و مثبت).
  • نوع پیش‌فرض اعداد صحیح i32 است.
  • usize برای اندیس آرایه‌ها و اندازه‌ی مجموعه‌ها استفاده می‌شود.

روش‌های نوشتن عدد:

fn main() {
    let decimal = 98_222;
    let hex = 0xff;
    let octal = 0o77;
    let binary = 0b1111_0000;
    let byte = b'A'; // فقط u8
    println!("{decimal} {hex} {octal} {binary} {byte}");
}

سرریز عدد (Integer Overflow)

اگر مقداری از محدوده‌ی نوع خارج شود:

  • در حالت debug: برنامه panic می‌کند.
  • در حالت release: مقدار به‌صورت دوری برمی‌گردد (wrap).

برای کنترل صریح، متدهای آماده هست:

fn main() {
    let x: u8 = 250;
    println!("{}", x.wrapping_add(10));            // 4
    println!("{:?}", x.checked_add(10));           // None
    println!("{:?}", x.checked_add(5));            // Some(255)
    println!("{}", x.saturating_add(10));          // 255
    println!("{:?}", x.overflowing_add(10));       // (4, true)
}

Tuple

ساختار match قدرتمندترین ابزار کنترل جریان در Rust است و در فصل Enum به‌طور کامل بررسی می‌شود. نگاهی کوتاه:

fn main() {
    let n = 3;
    match n {
        1 => println!("یک"),
        2 | 3 => println!("دو یا سه"),
        4..=9 => println!("چهار تا نه"),

}

تمرین

  1. برنامه‌ای بنویسید که اعداد ۱ تا ۱۰۰ را چاپ کند. مضرب‌های ۳ را "Fizz" و مضرب‌های ۵ را "Buzz" و مضرب هر دو را "FizzBuzz" چاپ کند.
  2. با while فاکتوریل ۱۰ را حساب کنید.
  3. با loop و break اولین عددی که مربعش از ۱۰۰۰ بزرگ‌تر است را پیدا کنید.
  4. با دو حلقه‌ی تو در تو جدول ضرب ۱ تا ۹ را چاپ کنید.

حالا به مهم‌ترین مفهوم Rust می‌رسیم: Ownership.

Ownership (مالکیت)

Ownership مهم‌ترین و متمایزترین ویژگی Rust است. با آن، Rust مدیریت حافظه را بدون Garbage Collector و بدون نیاز به آزاد کردن دستی حافظه انجام می‌دهد و در عین حال ایمن می‌ماند.

مرور: Stack و Heap

  • Stack: حافظه‌ای منظم و سریع (آخرین ورودی، اولین خروجی). فقط داده‌هایی با اندازه‌ی ثابت و معلوم در آن قرار می‌گیرند.
  • Heap: حافظه‌ای انعطاف‌پذیر برای داده‌هایی که اندازه‌شان در زمان کامپایل معلوم نیست یا تغییر می‌کند. تخصیص در آن کندتر است و با اشاره‌گر (pointer) به آن دسترسی داریم.

مشکلاتی که در زبان‌های دیگر پیش می‌آید:

  • C/C++: برنامه‌نویس باید دستی حافظه را آزاد کند. فراموش کردن = نشت حافظه. آزاد کردن دوباره = باگ امنیتی.
  • Java/Python/Go: Garbage Collector حافظه را آزاد می‌کند اما هزینه‌ی زمان اجرا دارد.
  • Rust: قوانین مالکیت در زمان کامپایل بررسی می‌شوند و هزینه‌ی اجرایی ندارند.

سه قانون Ownership

  1. هر مقدار در Rust یک مالک (owner) دارد.
  2. در هر زمان فقط یک مالک وجود دارد.
  3. وقتی مالک از scope خارج شود، مقدار آزاد (drop) می‌شود.

نوع String

برای دیدن Ownership به نوعی با داده‌ی heap نیاز داریم. String همین‌طور است:

fn main() {
    let mut s = String::from("hello");
    s.push_str(", world!");
    println!("{s}");
} // اینجا s از scope خارج می‌شود و Rust خودکار تابع drop را صدا می‌زند

Rust در انتهای } به‌طور خودکار حافظه را آزاد می‌کند. (این الگو در C++ با نام RAII شناخته می‌شود.)

Move (انتقال مالکیت)

fn main() {
    let s1 = String::from("hello");
    let s2 = s1;          // مالکیت از s1 به s2 منتقل می‌شود (move)

    println!("{s1}, world!"); // ✗ خطا: s1 دیگر معتبر نیست
}

چرا؟ String از سه بخش تشکیل شده: اشاره‌گر به heap، طول و ظرفیت. وقتی s2 = s1 می‌نویسیم، این سه مقدار کپی می‌شوند ولی داده‌ی heap کپی نمی‌شود. اگر هر دو متغیر معتبر می‌ماندند، در پایان scope هر دو سعی می‌کردند همان حافظه را آزاد کنند (double free). Rust برای جلوگیری از این مشکل، s1 را نامعتبر می‌کند.

Clone (کپی عمیق)

اگر واقعاً می‌خواهید داده‌ی heap کپی شود:

fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();
    println!("s1 = {s1}, s2 = {s2}");
}

clone ممکن است پرهزینه باشد، پس Rust آن را صریح می‌خواهد.

Copy: داده‌های روی Stack

انواعی که اندازه‌ی ثابت دارند و کپی کردنشان ارزان است، Copy هستند و move نمی‌شوند:

fn main() {
    let x = 5;
    let y = x;
    println!("x = {x}, y = {y}"); // هر دو معتبرند
}

انواع Copy عبارت‌اند از:

  • همه‌ی اعداد صحیح و اعشاری
  • bool و char
  • tuple هایی که فقط شامل انواع Copy هستند، مثل (i32, i32)
  • reference های غیرقابل‌تغییر (&T)

Ownership و توابع

پاس دادن مقدار به تابع هم مثل انتساب، آن را move یا copy می‌کند:

fn main() {
    let s = String::from("hello");
    takes_ownership(s);          // s اینجا move می‌شود
    // println!("{s}");          // ✗ خطا: دیگر معتبر نیست

    let x = 5;
    makes_copy(x);               // x از نوع Copy است
    println!("{x}");             // ✓ هنوز معتبر
}

fn takes_ownership(some_string: String) {
    println!("{some_string}");
} // some_string اینجا drop می‌شود

fn makes_copy(some_integer: i32) {
    println!("{some_integer}");
}

مقدار بازگشتی هم مالکیت را منتقل می‌کند:

fn main() {
    let s1 = gives_ownership();
    let s2 = String::from("hello");
    let s3 = takes_and_gives_back(s2);
    println!("{s1} {s3}");
}

fn gives_ownership() -> String {
    String::from("yours")
}

fn takes_and_gives_back(a_string: String) -> String {
    a_string
}

اما اگر هر بار برای استفاده از یک مقدار در تابع مجبور باشیم آن را پس بگیریم، کار خسته‌کننده می‌شود:

fn main() {
    let s1 = String::from("hello");
    let (s2, len) = calculate_length(s1);
    println!("طول '{s2}' برابر است با {len}");
}

fn calculate_length(s: String) -> (String, usize) {
    let length = s.len();
    (s, length)
}

راه‌حل بهتر، Reference و Borrowing است.

Drop

وقتی مقدار از scope خارج شود، Rust تابع drop را صدا می‌زند. می‌توانید رفتار آن را برای نوع خودتان با trait Drop تعیین کنید:

struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("{} آزاد شد", self.0);
    }
}

fn main() {
    let _a = Noisy("الف");
    let _b = Noisy("ب");
    println!("پایان main");
}

خروجی:

پایان main
ب آزاد شد
الف آزاد شد

متغیرها به ترتیب معکوس تعریف drop می‌شوند. برای آزاد کردن زودتر از موعد می‌توانید drop(x) را صدا بزنید.

خلاصه

مفهومتوضیح

Copyکپی ارزان روی stack؛ مقدار قبلی معتبر می‌ماند
Cloneکپی صریح و عمیق
Dropآزادسازی خودکار در پایان scope

  1. کدی بنویسید که با move خطا بدهد، پیغام خطا را بخوانید و آن را با clone درست کنید.
  2. تابعی بنویسید که یک String بگیرد و آن را بعد از اضافه کردن "!" برگرداند.
  3. چرا let a = [1, 2, 3]; let b = a; مشکلی ندارد ولی با Vec همین کار move است؟

Reference و Borrowing (قرض‌گیری)

در فصل قبل دیدیم که پس دادن مالکیت پس از هر فراخوانی خسته‌کننده است. راه‌حل: به‌جای انتقال مالکیت، مقدار را قرض بدهیم. این کار با Reference (مرجع) و علامت & انجام می‌شود.

Reference غیرقابل‌تغییر (&T)

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // قرض دادن s1
    println!("طول '{s1}' برابر است با {len}"); // s1 هنوز معتبر است
}

fn calculate_length(s: &String) -> usize {
    s.len()
} // s از scope خارج می‌شود اما چون مالک نیست، چیزی drop نمی‌شود

یک reference همیشه به یک مقدار معتبر اشاره می‌کند. به عمل ساختن reference می‌گویند borrowing.

با reference غیرقابل‌تغییر نمی‌توان مقدار را عوض کرد:

fn main() {
    let s = String::from("hello");
    change(&s);
}

fn change(some_string: &String) {
    some_string.push_str(", world"); // ✗ خطا: نمی‌توان مقدار قرض‌گرفته را تغییر داد
}

Reference قابل‌تغییر (&mut T)

fn main() {
    let mut s = String::from("hello");
    change(&mut s);
    println!("{s}");
}

fn change(some_string: &mut String) {
    some_string.push_str(", world");
}

دقت کنید: متغیر باید mut باشد و هنگام فراخوانی هم &mut بنویسید.

قوانین Borrowing

در هر لحظه، شما می‌توانید یکی از این دو حالت را داشته باشید:

  • هر تعداد reference غیرقابل‌تغییر (&T)
  • دقیقاً یک reference قابل‌تغییر (&mut T)

و همیشه: reference ها باید معتبر باشند (هرگز dangling نباشند).

چرا فقط یک &mut؟

برای جلوگیری از data race:

fn main() {
    let mut s = String::from("hello");

    let r1 = &mut s;
    let r2 = &mut s; // ✗ خطا: بیش از یک قرض قابل‌تغییر

    println!("{r1}, {r2}");
}

ترکیب &T و &mut T

fn main() {
    let mut s = String::from("hello");

    let r1 = &s;     // مشکلی نیست
    let r2 = &s;     // مشکلی نیست
    let r3 = &mut s; // ✗ خطا: وقتی r1 و r2 زنده‌اند نمی‌شود قرض قابل‌تغییر گرفت

    println!("{r1}, {r2}, {r3}");
}

منطقش این است: کسی که فقط می‌خواند، انتظار ندارد مقدار زیر دستش عوض شود.

NLL: عمر reference تا آخرین استفاده است

Reference از جایی که ساخته می‌شود تا آخرین جایی که استفاده می‌شود زنده است (نه تا انتهای بلوک). این قابلیت را Non-Lexical Lifetimes (NLL) می‌گویند:

fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &s;
    println!("{r1} و {r2}"); // آخرین استفاده از r1 و r2

    let r3 = &mut s; // ✓ حالا مشکلی نیست
    r3.push_str("!");
    println!("{r3}");
}

Dangling Reference

در زبان‌هایی مثل C ممکن است اشاره‌گری به حافظه‌ی آزادشده بسازید. در Rust کامپایلر جلوی آن را می‌گیرد:

fn main() {
    let r = dangle();
}

fn dangle() -> &String { // ✗ خطا: مقداری برای قرض دادن وجود ندارد
    let s = String::from("hello");
    &s
} // s اینجا drop می‌شود و reference به حافظه‌ی نامعتبر اشاره می‌کند

راه‌حل: مالکیت را برگردانید.

fn main() {
    let s = no_dangle();
    println!("{s}");
}

fn no_dangle() -> String {
    String::from("hello")
}

تفاوت reference با pointer

  • reference ها در Rust همیشه غیر null و معتبر هستند.
  • با عملگر * می‌توانید به مقدار اشاره‌شده دسترسی بگیرید (dereference):
fn main() {
    let mut x = 10;
    let r = &mut x;
    *r += 5;
    println!("{x}");
}

در بیشتر مواقع (مثل فراخوانی متد) Rust خودکار dereference می‌کند و نیازی به * نیست.

خلاصه

نوعنوشتارتعداد مجاز همزمان
قرض فقط‌خواندنی&Tهر تعداد
قرض قابل‌تغییر&mut Tفقط یکی (و بدون &T همزمان)

تمرین

  1. تابعی بنویسید که با &Vec<i32> مجموع عناصر را حساب کند.
  2. تابعی بنویسید که با &mut Vec<i32> عنصری به انتها اضافه کند.
  3. کدی بنویسید که دو &mut همزمان بگیرد و خطای کامپایلر را بخوانید.
  4. تابعی بنویسید که بزرگ‌ترین عدد یک آرایه را به‌صورت &i32 برگرداند (راهنمایی: به lifetime ها در فصل ۱۷ نیاز پیدا می‌کنید؛ فعلاً با &[i32] به‌عنوان ورودی امتحان کنید).

فصل بعد: Slice.

Slice

Slice یک reference به بخشی پیوسته از یک مجموعه است، بدون اینکه مالکیت آن را داشته باشد.

مسئله: اولین کلمه‌ی یک رشته

تابعی می‌خواهیم که اولین کلمه (تا اولین فاصله) را برگرداند. اگر فقط اندیس را برگردانیم:

fn first_word_end(s: &String) -> usize {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }
    s.len()
}

fn main() {
    let mut s = String::from("hello world");
    let end = first_word_end(&s); // 5
    s.clear();                    // رشته خالی شد ولی end هنوز 5 است!
    println!("{end}");
}

مشکل این است که اندیس end هیچ ارتباطی با خود رشته ندارد و بعد از تغییر رشته بی‌معنی می‌شود. Slice این مشکل را در زمان کامپایل حل می‌کند.

String Slice

fn main() {
    let s = String::from("hello world");

    let hello = &s[0..5];
    let world = &s[6..11];
    println!("{hello} {world}");

    // میان‌بُرها
    let a = &s[..5];   // از ابتدا
    let b = &s[6..];   // تا انتها
    let c = &s[..];    // کل رشته
    println!("{a} {b} {c}");
}

نوع slice رشته &str است. (همین نوع رشته‌های literal مثل "hello" هم هست؛ آن‌ها slice هایی به داده‌ی داخل خود برنامه‌ی باینری هستند.)

بازنویسی first_word

fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[..i];
        }
    }
    s
}

fn main() {
    let my_string = String::from("hello world");
    println!("{}", first_word(&my_string));       // از String
    println!("{}", first_word(&my_string[..]));   // از slice
    println!("{}", first_word("hello world"));    // از literal
}

قاعده‌ی طلایی: پارامتر تابع را &str بگیرید، نه &String. این کار تابع را انعطاف‌پذیرتر می‌کند.

حالا اگر بعد از گرفتن slice رشته را تغییر بدهیم، کامپایلر جلویمان را می‌گیرد:

fn first_word(s: &str) -> &str {
    s.split(' ').next().unwrap_or(s)
}

fn main() {
    let mut s = String::from("hello world");
    let word = first_word(&s);
    s.clear();                // ✗ خطا: s هنوز توسط word قرض گرفته شده
    println!("{word}");
}

نکته‌ی مهم درباره‌ی یونیکد و متن فارسی

رشته‌های Rust همیشه UTF-8 هستند. اندیس‌ها در slice ها بایت هستند، نه کاراکتر. حروف فارسی هر کدام ۲ بایت (و برخی نمادها بیشتر) جا می‌گیرند:

fn main() {
    let s = "سلام";
    println!("{}", s.len());          // 8 (بایت)
    println!("{}", s.chars().count()); // 4 (کاراکتر)
}

اگر slice را وسط یک کاراکتر ببُرید، برنامه panic می‌کند:

fn main() {
    let s = String::from("سلام");
    let cut = s.len() / 8; // 1
    println!("{}", &s[0..cut]); // panic: وسط کاراکتر
}

برای کار با کاراکترها از chars() استفاده کنید:

fn main() {
    let s = "سلام دنیا";
    for c in s.chars() {
        print!("[{c}]");
    }
    println!();

    let first_two: String = s.chars().take(2).collect();
    println!("{first_two}");
}

Slice آرایه و Vec

slice فقط برای رشته نیست:

fn main() {
    let a = [1, 2, 3, 4, 5];
    let slice: &[i32] = &a[1..3];
    println!("{slice:?}");            // [2, 3]
    println!("{}", slice.len());      // 2
}

نوع &[T] یعنی "slice ای از T". توابعی که &[T] می‌گیرند با آرایه و Vec هر دو کار می‌کنند:

fn sum(numbers: &[i32]) -> i32 {
    let mut total = 0;
    for n in numbers {
        total += n;
    }
    total
}

fn main() {
    let arr = [1, 2, 3];
    let v = vec![10, 20, 30, 40];
    println!("{} {} {}", sum(&arr), sum(&v), sum(&v[1..3]));
}

تمرین

  1. تابعی بنویسید که دومین کلمه‌ی یک رشته را برگرداند.
  2. تابعی بنویسید که &[i32] بگیرد و بزرگ‌ترین عنصر را به‌صورت Option<i32> برگرداند.
  3. بررسی کنید "ایران".len() چه عددی می‌دهد و چرا.

فصل بعد: Struct.

Struct

Struct (ساختار) اجازه می‌دهد چند مقدار مرتبط را با نام‌های معنی‌دار در یک نوع جدید کنار هم بگذارید.

تعریف و ساخت

struct User {
    username: String,
    email: String,
    sign_in_count: u64,
    active: bool,
}

fn main() {
    let mut user1 = User {
        email: String::from("ali@example.com"),
        username: String::from("ali"),
        active: true,
        sign_in_count: 1,
    };

    user1.email = String::from("new@example.com");
    println!("{} {}", user1.username, user1.email);
}
  • ترتیب فیلدها هنگام ساخت مهم نیست.
  • برای تغییر یک فیلد، کل متغیر باید mut باشد (نمی‌توان فقط یک فیلد را mutable کرد).

میان‌بر مقداردهی (Field Init Shorthand)

وقتی نام پارامتر با نام فیلد یکی باشد:

struct User {
    username: String,
    email: String,
}

fn build_user(email: String, username: String) -> User {
    User { email, username }
}

fn main() {
    let u = build_user("a@b.com".to_string(), "reza".to_string());
    println!("{}", u.username);
}

Struct Update Syntax

ساخت نمونه‌ی جدید بر پایه‌ی نمونه‌ی قبلی:

#[derive(Debug)]
struct Config {
    width: u32,
    height: u32,
    title: String,
}

fn main() {
    let base = Config { width: 800, height: 600, title: String::from("پایه") };
    let wide = Config { width: 1920, ..base };
    println!("{wide:?}");
    // توجه: title از base به wide move شد، پس base.title دیگر معتبر نیست
}

Tuple Struct و Unit-like Struct

struct Color(u8, u8, u8);
struct Point(f64, f64, f64);
struct AlwaysEqual; // بدون فیلد

fn main() {
    let red = Color(255, 0, 0);
    let origin = Point(0.0, 0.0, 0.0);
    let _marker = AlwaysEqual;
    println!("{} {}", red.0, origin.2);
}

Color و Point دو نوع متفاوت هستند حتی اگر ساختار داخلی‌شان شبیه باشد.

چاپ struct با Debug

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect = Rectangle { width: 30, height: 50 };
    println!("{rect:?}");   // Rectangle { width: 30, height: 50 }
    println!("{rect:#?}");  // چاپ چندخطی و زیبا
    dbg!(&rect);            // چاپ در stderr همراه شماره خط
}

خط #[derive(Debug)] را attribute می‌گویند و پیاده‌سازی خودکار trait به نام Debug را درخواست می‌کند.

متدها (impl)

متد، تابعی است که داخل بلوک impl برای یک نوع تعریف می‌شود و اولین پارامترش self است:

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }

    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }

    fn scale(&mut self, factor: u32) {
        self.width *= factor;
        self.height *= factor;
    }
}

fn main() {
    let mut rect1 = Rectangle { width: 30, height: 50 };
    let rect2 = Rectangle { width: 10, height: 40 };

    println!("مساحت: {}", rect1.area());
    println!("جا می‌شود؟ {}", rect1.can_hold(&rect2));

    rect1.scale(2);
    println!("{rect1:?}");
}

سه شکل self:

شکلمعنی
&selfفقط خواندن (رایج‌ترین)
&mut selfخواندن و تغییر
selfگرفتن مالکیت (مثلاً هنگام تبدیل به نوع دیگر)

نکته: Rust هنگام فراخوانی متد خودکار & ، &mut یا * را اضافه می‌کند (automatic referencing). به همین دلیل در Rust عملگر -> مثل C++ لازم نیست.

Associated Function (تابع وابسته)

توابعی در impl که self ندارند. با :: صدا زده می‌شوند و معمولاً سازنده (constructor) هستند:

struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn new(width: u32, height: u32) -> Self {
        Self { width, height }
    }

    fn square(size: u32) -> Self {
        Self { width: size, height: size }
    }
}

fn main() {
    let r = Rectangle::new(3, 4);
    let s = Rectangle::square(5);
    println!("{} {}", r.width * r.height, s.width);
}

Self در impl یعنی همان نوعی که در حال پیاده‌سازی‌اش هستیم. هر نوع می‌تواند چند بلوک impl داشته باشد.

الگوی Builder (پیشرفته‌تر)

برای ساخت اشیای با تنظیمات زیاد:

#[derive(Debug, Default)]
struct Server {
    host: String,
    port: u16,
    tls: bool,
}

impl Server {
    fn new(host: &str) -> Self {

}

Enum، match و Option

Enum (شمارشی) نوعی است که مقدارش می‌تواند یکی از چند حالت ممکن باشد. enum ها در Rust بسیار قدرتمندتر از زبان‌هایی مثل C یا Java هستند، چون هر حالت می‌تواند داده هم همراه داشته باشد.

تعریف ساده

#[derive(Debug)]
enum Direction {
    North,
    South,
    East,
    West,
}

fn main() {
    let d = Direction::North;
    println!("{d:?}");
}

Enum با داده

هر حالت می‌تواند داده‌ی متفاوتی داشته باشد:

#[derive(Debug)]
enum Message {
    Quit,                       // بدون داده
    Move { x: i32, y: i32 },    // مثل struct
    Write(String),              // مثل tuple با یک مقدار
    ChangeColor(u8, u8, u8),    // مثل tuple با سه مقدار
}

impl Message {
    fn describe(&self) -> String {
        match self {
            Message::Quit => String::from("خروج"),
            Message::Move { x, y } => format!("حرکت به ({x}, {y})"),
            Message::Write(text) => format!("نوشتن: {text}"),
            Message::ChangeColor(r, g, b) => format!("رنگ: rgb({r},{g},{b})"),
        }
    }
}

fn main() {
    let msgs = [
        Message::Quit,
        Message::Move { x: 10, y: 20 },
        Message::Write(String::from("سلام")),
        Message::ChangeColor(255, 0, 128),
    ];
    for m in &msgs {
        println!("{}", m.describe());
    }
}

match

match مقدار را با چند الگو (pattern) مقایسه می‌کند و اولین الگوی منطبق را اجرا می‌کند:

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}

fn main() {
    println!("{}", value_in_cents(Coin::Dime));
}

match باید جامع (exhaustive) باشد

اگر یکی از حالت‌ها را فراموش کنید، کد کامپایل نمی‌شود. این یکی از بزرگ‌ترین مزیت‌های enum ها در Rust است؛ وقتی حالت جدیدی به enum اضافه کنید، کامپایلر همه‌ی جاهایی که باید به‌روز شوند را نشان می‌دهد.

#![allow(unused)]
fn main() {
enum Light { Red, Yellow, Green }

fn action(l: Light) -> &'static str {
    match l {
        Light::Red => "توقف",
        Light::Green => "حرکت",
        // ✗ خطا: Yellow پوشش داده نشده
    }
}
}

الگوی catch-all

fn main() {
    let dice_roll = 9;
    match dice_roll {

استخراج داده از enum

enum UsState { Alabama, Alaska }

enum Coin {

}

fn describe(coin: Coin) {

Option: جایگزین null

بسیاری از زبان‌ها null دارند که "اختراع یک میلیارد دلاری اشتباه" نام گرفته است. Rust null ندارد. به‌جایش enum استاندارد Option<T> را دارد:

#![allow(unused)]
fn main() {
enum Option<T> {
    None,
    Some(T),
}
}
fn main() {
    let some_number = Some(5);
    let some_text = Some("سلام");
    let absent: Option<i32> = None;
    println!("{some_number:?} {some_text:?} {absent:?}");
}

چرا بهتر از null است؟ چون Option<i32> و i32 دو نوع متفاوت هستند. اگر مقدار ممکن است وجود نداشته باشد، کامپایلر شما را مجبور می‌کند حالت None را مدیریت کنید:

fn main() {
    let x: i8 = 5;
    let y: Option<i8> = Some(5);
    let sum = x + y; // ✗ خطا: نمی‌توان i8 را با Option<i8> جمع کرد
}

استفاده از Option

fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1),
    }
}

fn main() {
    println!("{:?}", plus_one(Some(5)));
    println!("{:?}", plus_one(None));
}

متدهای مفید Option:

fn main() {
    let a = Some(4);
    let b: Option<i32> = None;

    println!("{}", a.unwrap_or(0));          // 4
    println!("{}", b.unwrap_or(0));          // 0
    println!("{:?}", a.map(|x| x * 2));      // Some(8)
    println!("{}", a.is_some());             // true
    println!("{:?}", a.and_then(|x| if x > 3 { Some(x) } else { None }));
    println!("{}", b.unwrap_or_default());   // 0
}

هشدار: unwrap() اگر مقدار None باشد برنامه را panic می‌کند. در کد واقعی ترجیحاً از match، if let، unwrap_or یا عملگر ? استفاده کنید.

if let و let else

وقتی فقط یک الگو برایتان مهم است، match کامل زیادی است:

fn main() {
    let config_max = Some(3u8);

    // به‌جای match با _ => ()
    if let Some(max) = config_max {
        println!("حداکثر: {max}");
    }

    // با else
    let value: Option<u8> = None;
    if let Some(v) = value {
        println!("{v}");
    } else {
        println!("مقداری نیست");
    }
}

let else برای خروج زودهنگام عالی است:

fn describe(input: Option<&str>) -> String {
    let Some(text) = input else {
        return String::from("خالی");
    };
    format!("متن: {text}")
}

fn main() {
    println!("{}", describe(Some("سلام")));
    println!("{}", describe(None));
}

و while let برای حلقه تا زمانی که الگو منطبق باشد:

fn main() {
    let mut stack = vec![1, 2, 3];
    while let Some(top) = stack.pop() {
        println!("{top}");
    }
}

تمرین

  1. enum به نام Shape با حالت‌های Circle(f64)، Rectangle(f64, f64) و Triangle(f64, f64, f64) بسازید و تابع محاسبه‌ی مساحت را با match بنویسید.
  2. تابعی بنویسید که دو عدد بگیرد و حاصل تقسیم را به‌صورت Option<f64> برگرداند (None هنگام تقسیم بر صفر).
  3. enum به نام TrafficLight بنویسید و متدی برای برگرداندن مدت زمان هر چراغ نوشته و سپس یک حالت جدید اضافه کنید تا ببینید کامپایلر چه می‌گوید.

مجموعه‌ها: Vec، String و HashMap

کتابخانه‌ی استاندارد Rust چند ساختار داده‌ی مفید دارد که داده‌هایشان روی heap ذخیره می‌شود و می‌توانند در زمان اجرا بزرگ و کوچک شوند. سه مورد پرکاربرد آن‌ها: Vec، String و HashMap.

Vec: آرایه‌ی پویا

ساخت

    v.push(7);

}

خواندن عناصر

دو روش دارید:

fn main() {

    println!("{third}");

Vec و قوانین borrowing

fn main() {
    let mut v = vec![1, 2, 3, 4, 5];
    let first = &v[0];  // قرض غیرقابل‌تغییر
    v.push(6);          // ✗ خطا: push ممکن است حافظه را جابه‌جا کند

چرا؟ چون push ممکن است Vec را در جای دیگری از حافظه بازتخصیص دهد و first به حافظه‌ی نامعتبر اشاره کند. Rust از این باگ در زمان کامپایل جلوگیری می‌کند.

پیمایش

}

String

String در برابر &str

  • str: داده‌ی متنی (معمولاً به‌صورت &str دیده می‌شود)، تغییرناپذیر.
  • String: متن قابل رشد و دارای مالک روی heap. در واقع یک Vec<u8> است که UTF-8 بودنش تضمین شده.

ساخت و تغییر

fn main() {
    let mut s = String::new();
    s.push_str("سلام");
    s.push(' ');
    s += "دنیا";               // عملگر +=
    println!("{s}");

    let a = String::from("Hello, ");
    let b = String::from("world!");
    let c = a + &b;            // a به اینجا move می‌شود
    println!("{c}");

    let x = String::from("tic");
    let y = String::from("tac");
    let z = String::from("toe");
    let joined = format!("{x}-{y}-{z}");   // هیچ کدام move نمی‌شوند
    println!("{joined} {x}");
}

اندیس‌گذاری ممنوع است

fn main() {
    let s = String::from("hello");
    let h = s[0]; // ✗ خطا: String را نمی‌توان اندیس‌گذاری کرد
}

دلیل: رشته‌ها UTF-8 هستند و کاراکتر ممکن است بیش از یک بایت باشد. اندیس s[0] معنی مشخصی ندارد (بایت؟ کاراکتر؟ grapheme؟). به‌جایش:

fn main() {

    println!("{}", s.chars().count());    // کاراکترها

}

Package، Crate و Module

وقتی برنامه بزرگ‌تر می‌شود، باید کد را سازمان‌دهی کنیم. سیستم ماژول Rust چند سطح دارد:

مفهومتوضیح
Packageیک یا چند crate که با Cargo ساخته، تست و منتشر می‌شوند (دارای Cargo.toml)
Crateیک واحد کامپایل: یا فایل اجرایی (binary) یا کتابخانه (library)
Moduleسازمان‌دهی داخل crate و کنترل خصوصی/عمومی بودن
Pathنام‌گذاری یک آیتم (تابع، struct و ...)

Crate Root

  • برای پروژه‌ی اجرایی: فایل src/main.rs
  • برای کتابخانه: فایل src/lib.rs

یک package می‌تواند یک lib.rs و چند binary داشته باشد (در پوشه‌ی src/bin/).

تعریف ماژول

mod restaurant {
    pub mod hosting {
        pub fn add_to_waitlist() {
            println!("به لیست انتظار اضافه شد");
        }
        fn seat_at_table() {}
    }

    mod serving {
        fn take_order() {}
    }
}

fn main() {
    restaurant::hosting::add_to_waitlist();
}

Path (مسیر)

  • مسیر مطلق: از ریشه‌ی crate با crate::
  • مسیر نسبی: از ماژول فعلی، یا با self:: و super::
mod restaurant {
    pub mod hosting {
        pub fn seat() {}
    }

    pub fn eat_at_restaurant() {
        crate::restaurant::hosting::seat(); // مطلق
        hosting::seat();                    // نسبی
    }

    fn deliver_order() {}

    pub mod back_of_house {
        pub fn fix_order() {
            cook_order();
            super::deliver_order(); // یک ماژول بالاتر
        }
        fn cook_order() {}
    }
}

fn main() {
    restaurant::eat_at_restaurant();
    restaurant::back_of_house::fix_order();
}

خصوصی و عمومی (pub)

قاعده: همه‌چیز به‌طور پیش‌فرض خصوصی است.

  • کد فرزند می‌تواند آیتم‌های خصوصی اجدادش را ببیند.
  • کد پدر نمی‌تواند آیتم‌های خصوصی فرزند را ببیند.

  • در enum، اگر enum عمومی باشد همه‌ی حالت‌هایش عمومی‌اند.
mod shop {

مدیریت خطا: panic، Result و عملگر ?

Rust خطاها را به دو دسته تقسیم می‌کند:

  • خطاهای بازیابی‌ناپذیر (unrecoverable): باگ‌هایی مثل دسترسی خارج از محدوده. با panic! برنامه متوقف می‌شود.
  • خطاهای بازیابی‌پذیر (recoverable): مثل نبودن فایل. با نوع Result<T, E> مدیریت می‌شوند.

Rust exception ندارد. خطاها بخشی از نوع برگشتی تابع هستند و نمی‌توان فراموششان کرد.

panic!

fn main() {
    panic!("اوه! مشکل جدی پیش آمد");
}

با اجرای panic، برنامه پیغام خطا را چاپ می‌کند، پشته را باز می‌کند (unwinding) و خارج می‌شود. برای دیدن ردپای کامل:

RUST_BACKTRACE=1 cargo run

در Cargo.toml می‌توانید با panic = "abort" در [profile.release] به‌جای unwinding فوراً برنامه را ببندید تا فایل باینری کوچک‌تر شود.

چه زمانی panic کنیم؟

  • وقتی برنامه در حالت غیرممکن قرار گرفته (نقض یک invariant)
  • در مثال‌ها، نمونه‌های اولیه و تست‌ها
  • وقتی ادامه دادن ناامن است

در بقیه‌ی موارد از Result استفاده کنید.

Result

#![allow(unused)]
fn main() {
enum Result<T, E> {
    Ok(T),
    Err(E),
}
}

use std::fs::File;

fn main() {

use std::fs::File;

fn main() {

        Ok(_) => println!("باز شد"),

            ErrorKind::NotFound => println!("فایل پیدا نشد"),

            other => println!("خطای دیگر: {other:?}"),

unwrap و expect

میان‌برهایی که در صورت Err panic می‌کنند:

fn main() {
    let n: i32 = "abc".parse().unwrap();       // panic با پیغام عمومی
    println!("{n}");
}
fn main() {
    let n: i32 = "abc".parse().expect("باید یک عدد معتبر باشد"); // پیغام دلخواه
    println!("{n}");
}

در کد واقعی expect را به unwrap ترجیح دهید چون پیغام روشن‌تری می‌دهد.

متدهای کاربردی Result

fn main() {
    let ok: Result<i32, String> = Ok(10);
    let err: Result<i32, String> = Err(String::from("بد"));

    println!("{}", ok.clone().unwrap_or(0));          // 10
    println!("{}", err.clone().unwrap_or(0));         // 0
    println!("{:?}", ok.clone().map(|x| x * 2));      // Ok(20)
    println!("{:?}", err.clone().map_err(|e| e.len()));  // Err(2)
    println!("{}", ok.is_ok());
    println!("{:?}", err.ok());                       // None
}

انتشار خطا با عملگر ?

نوشتن match برای هر خطا خسته‌کننده است. عملگر ? اگر مقدار Ok باشد آن را باز می‌کند و اگر Err باشد، همان‌جا از تابع برمی‌گردد و خطا را به فراخواننده می‌دهد:

use std::fs::File;
use std::io::{self, Read};

fn read_username_from_file() -> Result<String, io::Error> {
    let mut f = File::open("username.txt")?;
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}

fn main() {
    match read_username_from_file() {
        Ok(name) => println!("{name}"),
        Err(e) => println!("خطا: {e}"),
    }
}

نوع خطای اختصاصی

برای کتابخانه‌ها و برنامه‌های جدی، نوع خطای خودتان را تعریف کنید:

use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum ConfigError {
    Missing(String),
    InvalidNumber(ParseIntError),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::Missing(key) => write!(f, "کلید {key} پیدا نشد"),
            ConfigError::InvalidNumber(e) => write!(f, "عدد نامعتبر: {e}"),
        }
    }
}

impl std::error::Error for ConfigError {}

// این پیاده‌سازی اجازه می‌دهد ? خودکار ParseIntError را تبدیل کند
impl From<ParseIntError> for ConfigError {
    fn from(e: ParseIntError) -> Self {
        ConfigError::InvalidNumber(e)
    }
}

fn parse_port(value: Option<&str>) -> Result<u16, ConfigError> {
    let text = value.ok_or_else(|| ConfigError::Missing("port".to_string()))?;
    let port = text.parse::<u16>()?;  // ParseIntError → ConfigError با From
    Ok(port)
}

fn main() {
    println!("{:?}", parse_port(Some("8080")));
    println!("{}", parse_port(None).unwrap_err());
    println!("{}", parse_port(Some("abc")).unwrap_err());
}

فصل بعد: Generics.

Generics

Generics (انواع عمومی) اجازه می‌دهند کدی بنویسید که با چند نوع مختلف کار کند، بدون اینکه آن را برای هر نوع تکرار کنید. پیش‌تر هم با آن‌ها سر و کار داشته‌اید: Vec<T>، Option<T>، Result<T, E> و HashMap<K, V>.

مسئله: تکرار کد

        }

    largest
}

fn largest_char(list: &[char]) -> &char {
    let mut largest = &list[0];

توابع Generic

fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}

fn main() {
    println!("{}", largest(&[34, 50, 25]));
    println!("{}", largest(&['y', 'm', 'a']));
    println!("{}", largest(&[1.5, 0.3]));
}

بخش <T: PartialOrd> یعنی: "T هر نوعی می‌تواند باشد، به شرط آنکه قابل مقایسه با > باشد." به این شرط Trait Bound می‌گویند. اگر آن را حذف کنید، کامپایلر خطا می‌دهد چون نمی‌داند > روی T تعریف شده یا نه.

عملکرد: Monomorphization

آیا generics در زمان اجرا هزینه دارند؟ خیر. کامپایلر در زمان کامپایل برای هر نوعی که واقعاً استفاده شده، یک نسخه‌ی مجزا از کد تولید می‌کند (monomorphization). یعنی Option<i32> و Option<f64> در باینری نهایی دو نوع جداگانه‌اند و سرعت اجرا دقیقاً مثل نوشتن دستی هر دو است. هزینه‌اش فقط زمان کامپایل و اندازه‌ی کمی بزرگ‌تر باینری است.

فصل بعد: Lifetime.

Lifetime

Lifetime (طول عمر) یکی از مفاهیمی است که مبتدی‌ها را می‌ترساند، اما ایده‌ی اصلی ساده است: هر reference فقط تا زمانی معتبر است که چیزی که به آن اشاره می‌کند زنده باشد. کامپایلر Rust این را بررسی می‌کند.

در بیشتر موارد lifetime ها ضمنی هستند و خودتان چیزی نمی‌نویسید. فقط وقتی کامپایلر نتواند حدس بزند، باید توضیحشان بدهید.

جلوگیری از Dangling Reference

fn main() {
    let r;
    {
        let x = 5;
        r = &x;       // ✗ خطا: x به‌اندازه‌ی کافی عمر نمی‌کند
    }
    println!("{r}");  // r به حافظه‌ی آزادشده اشاره می‌کند!
}

کامپایلر با Borrow Checker این مقایسه را انجام می‌دهد: عمر r بزرگ‌تر از عمر x است، پس خطا.

چرا گاهی به annotation نیاز داریم؟

#![allow(unused)]
fn main() {
fn longest(x: &str, y: &str) -> &str {  // ✗ خطا: missing lifetime specifier
    if x.len() > y.len() { x } else { y }
}
}

کامپایلر نمی‌داند خروجی از x است یا y. در نتیجه نمی‌تواند عمر خروجی را بررسی کند.

نشانه‌گذاری Lifetime

نشانه با ' شروع می‌شود (معمولاً 'a، 'b):

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

fn main() {
    let s1 = String::from("long string is long");
    let result;
    {
        let s2 = String::from("xyz");
        result = longest(s1.as_str(), s2.as_str());

    }
}

معنی: "هر دو ورودی و خروجی حداقل به اندازه‌ی 'a عمر می‌کنند، که در عمل برابر با کوتاه‌ترین عمر بین دو ورودی است."

نکته مهم: annotation ها عمر هیچ چیز را تغییر نمی‌دهند. فقط رابطه‌ی بین عمرها را به کامپایلر می‌گویند.

معنی: نمونه‌ی Excerpt نمی‌تواند بیشتر از متنی که به آن اشاره می‌کند عمر کند.

ساده‌ترین راه: اگر نمی‌خواهید با lifetime درگیر شوید، به‌جای reference در struct از نوع‌های دارای مالک مثل String استفاده کنید.

قواعد Lifetime Elision

چرا در fn first_word(s: &str) -> &str نیازی به annotation نبود؟ چون کامپایلر سه قاعده دارد که خودکار اعمال می‌شوند:

  1. هر پارامتر reference یک lifetime مجزا می‌گیرد.
  2. اگر دقیقاً یک lifetime ورودی وجود داشته باشد، به همه‌ی خروجی‌ها اعمال می‌شود.
  3. اگر یکی از ورودی‌ها &self یا &mut self باشد، lifetime آن به خروجی‌ها داده می‌شود.

اگر بعد از این قواعد هنوز مبهم بود، خطا می‌گیرید و خودتان باید بنویسید.

Lifetime ی 'static

عمر 'static یعنی تا پایان برنامه زنده است. رشته‌های literal این‌طورند:

fn main() {
    let s: &'static str = "من در باینری برنامه ذخیره شده‌ام";
    println!("{s}");
}

هشدار: وقتی کامپایلر پیشنهاد می‌دهد 'static بگذارید، معمولاً راه‌حل درست نیست. بیشتر وقت‌ها مشکل طراحی است و باید مالکیت را درست کنید.

فصل بعد: Closure.

Closure

Closure تابعی بی‌نام است که می‌تواند متغیرهای محیط اطرافش را capture کند. در زبان‌های دیگر به آن lambda هم می‌گویند.

نوشتار

fn main() {
    let add_one = |x: i32| -> i32 { x + 1 };
    let add_two = |x| x + 2;        // نوع و آکولاد اختیاری
    let hello = || println!("سلام");

    println!("{}", add_one(5));
    println!("{}", add_two(5));
    hello();
}
  • پارامترها بین | | نوشته می‌شوند.
  • معمولاً نوع‌ها را کامپایلر حدس می‌زند. اما با اولین فراخوانی، نوع ثابت می‌شود:
fn main() {
    let identity = |x| x;
    let s = identity(String::from("hello"));
    let n = identity(5);   // ✗ خطا: نوع قبلاً String تعیین شده
}

Capture محیط

برخلاف توابع معمولی، closure می‌تواند به متغیرهای اطرافش دسترسی داشته باشد:

fn main() {
    let threshold = 10;
    let is_big = |n: i32| n > threshold;   // threshold را capture می‌کند

    println!("{} {}", is_big(5), is_big(15));
}

capture به سه شکل انجام می‌شود (کامپایلر خودش کم‌ترین سطح لازم را انتخاب می‌کند):

  1. قرض غیرقابل‌تغییر (&T): فقط خواندن
  2. قرض قابل‌تغییر (&mut T): تغییر
  3. گرفتن مالکیت (move): مقدار به داخل closure منتقل می‌شود
fn main() {
    // ۱. فقط خواندن
    let list = vec![1, 2, 3];
    let only_reads = || println!("{list:?}");
    only_reads();
    println!("{list:?}");   // هنوز می‌توان استفاده کرد

    // ۲. تغییر
    let mut count = 0;
    let mut inc = || count += 1;
    inc();
    inc();
    println!("{count}");    // 2

    // ۳. گرفتن مالکیت
    let text = String::from("سلام");
    let consume = move || println!("{text}");
    consume();
    // println!("{text}");  // ✗ text به closure منتقل شد
}

کلمه‌ی move

move مالکیت همه‌ی متغیرهای capture شده را به closure می‌دهد. وقتی لازم است که closure از scope فعلی بیشتر عمر کند، مثلاً در thread ها:

use std::thread;

fn main() {
    let v = vec![1, 2, 3];

    let handle = thread::spawn(move || {
        println!("از thread: {v:?}");
    });

    handle.join().unwrap();
}

سه trait برای closure ها

بسته به اینکه closure با متغیرهای capture شده چه می‌کند، یکی یا چند تا از این trait ها را به‌طور خودکار پیاده می‌کند:

ساخت iterator اختصاصی

struct Countdown {
    n: u32,
}

impl Iterator for Countdown {
    type Item = u32;

    fn next(&mut self) -> Option<u32> {
        if self.n == 0 {
            None
        } else {
            let current = self.n;
            self.n -= 1;
            Some(current)
        }
    }
}

fn main() {
    let c = Countdown { n: 5 };
    let v: Vec<u32> = c.filter(|x| x % 2 == 1).collect();
    println!("{v:?}"); // [5, 3, 1]

    let sum: u32 = Countdown { n: 4 }.zip(Countdown { n: 4 }.skip(1)).map(|(a, b)| a * b).sum();
    println!("{sum}");
}

fn main() {

    // سبک حلقه
    let mut long_words = Vec::new();

        }
    }

    // سبک iterator
    let long_words2: Vec<String> = words
        .iter()
        .filter(|w| w.len() > 3)
        .map(|w| w.to_uppercase())

}

Smart Pointer: Box، Rc و RefCell

Pointer یعنی متغیری که آدرس حافظه را نگه می‌دارد. reference ها (&T) ساده‌ترین نوع pointer در Rust هستند و فقط قرض می‌گیرند. Smart Pointer ها ساختارهایی هستند که مثل pointer رفتار می‌کنند اما متادیتای اضافه و قابلیت‌های بیشتر دارند و معمولاً مالک داده‌اند. String و Vec هم از نظر فنی smart pointer هستند.

Rc<T>: مالکیت چندگانه

گاهی یک مقدار باید چند مالک داشته باشد (مثل گره‌ای در گراف که چند یال به آن می‌رسد). Rc (Reference Counted) تعداد مالکان را می‌شمارد و وقتی صفر شد، مقدار را آزاد می‌کند:

use std::rc::Rc;

fn main() {
    let a = Rc::new(String::from("مشترک"));
    println!("تعداد: {}", Rc::strong_count(&a)); // 1

    let b = Rc::clone(&a);    // فقط شمارنده زیاد می‌شود؛ داده کپی نمی‌شود
    println!("تعداد: {}", Rc::strong_count(&a)); // 2

    {
        let c = Rc::clone(&a);
        println!("تعداد: {} {c}", Rc::strong_count(&a)); // 3
    }
    println!("تعداد: {}", Rc::strong_count(&a)); // 2
    println!("{b}");
}

نکات:

  • Rc فقط برای تک‌نخی (single-thread) است. برای چند‌نخی از Arc استفاده کنید (فصل ۲۱).
  • با Rc فقط دسترسی خواندنی دارید.
  • قرارداد: به‌جای a.clone() بنویسید Rc::clone(&a) تا معلوم باشد کپی ارزان است.

RefCell<T> و Interior Mutability

قوانین borrowing معمولاً در زمان کامپایل بررسی می‌شوند. RefCell<T> همان قوانین را در زمان اجرا بررسی می‌کند. این به شما اجازه می‌دهد از طریق reference غیرقابل‌تغییر، داده را تغییر دهید (Interior Mutability):

use std::cell::RefCell;

fn main() {
    let cell = RefCell::new(vec![1, 2, 3]);

    cell.borrow_mut().push(4);        // قرض قابل‌تغییر
    println!("{:?}", cell.borrow());  // قرض غیرقابل‌تغییر
}

اگر قوانین را نقض کنید، برنامه panic می‌کند (نه خطای کامپایل):

use std::cell::RefCell;

fn main() {
    let cell = RefCell::new(5);
    let _a = cell.borrow_mut();
    let _b = cell.borrow_mut(); // panic: already borrowed
}

Cell<T> گزینه‌ی سبک‌تر برای انواع Copy است:

use std::cell::Cell;

fn main() {
    let c = Cell::new(10);
    c.set(c.get() + 1);
    println!("{}", c.get());
}

ترکیب Rc و RefCell

الگوی رایج برای داده‌ی مشترک و قابل‌تغییر در برنامه‌ی تک‌نخی:

use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Account {
    balance: i32,
}

fn main() {
    let shared = Rc::new(RefCell::new(Account { balance: 100 }));

    let a = Rc::clone(&shared);
    let b = Rc::clone(&shared);

    a.borrow_mut().balance += 50;
    b.borrow_mut().balance -= 30;

    println!("{:?}", shared.borrow());
}

Weak<T> و چرخه‌ی مرجع

اگر دو Rc به هم اشاره کنند، شمارنده هیچ‌وقت صفر نمی‌شود و حافظه نشت می‌کند (Rust نشت را ممنوع نمی‌کند، فقط ایمن نگهش می‌دارد). برای شکستن چرخه از Weak استفاده کنید که مالکیت نمی‌دهد:

use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    value: i32,
    parent: RefCell<Weak<Node>>,
    children: RefCell<Vec<Rc<Node>>>,
}

fn main() {
    let leaf = Rc::new(Node {
        value: 3,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![]),
    });
    println!("پدر برگ: {:?}", leaf.parent.borrow().upgrade().map(|p| p.value));

    let branch = Rc::new(Node {
        value: 5,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![Rc::clone(&leaf)]),
    });

    *leaf.parent.borrow_mut() = Rc::downgrade(&branch);
    println!("پدر برگ: {:?}", leaf.parent.borrow().upgrade().map(|p| p.value));
    println!("strong={} weak={}", Rc::strong_count(&branch), Rc::weak_count(&branch));
    println!("{}", branch.children.borrow().len() + leaf.value as usize);
}

تمرین

  3. struct ی بسازید که با RefCell تعداد فراخوانی یک متد &self را بشمارد.

Concurrency: Thread، Channel و Mutex

یکی از وعده‌های Rust Fearless Concurrency یا "همزمانی بدون ترس" است: بسیاری از باگ‌های همزمانی (مثل data race) در Rust خطای کامپایل هستند، نه باگ نهفته در زمان اجرا.

مدل‌های ownership و type system که برای ایمنی حافظه ساخته شدند، همان ابزارهایی هستند که ایمنی همزمانی را هم تضمین می‌کنند.

ساخت Thread

use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..4 {
            println!("thread: {i}");
            thread::sleep(Duration::from_millis(1));
        }
    });

    for i in 1..3 {
        println!("main: {i}");
        thread::sleep(Duration::from_millis(1));
    }

    handle.join().unwrap();   // صبر تا پایان thread
}
  • thread::spawn یک thread سیستم‌عامل می‌سازد.
  • اگر main تمام شود، همه‌ی thread ها بسته می‌شوند. برای صبر کردن از join استفاده کنید.
  • ترتیب اجرا قطعی نیست.

move با thread

use std::thread;

fn main() {
    let v = vec![1, 2, 3];

    let handle = thread::spawn(move || {
        println!("{v:?}");
    });

    // println!("{v:?}"); // ✗ v به thread منتقل شد
    handle.join().unwrap();
}

بدون move، کامپایلر خطا می‌دهد چون ممکن است thread بیشتر از v عمر کند.

مقدار برگشتی

use std::thread;

fn main() {
    let handle = thread::spawn(|| (1..=100).sum::<u32>());
    let total = handle.join().unwrap();
    println!("{total}");
}

Scoped Thread

اگر مطمئنید thread ها قبل از پایان scope تمام می‌شوند، می‌توانید بدون move و بدون Arc، داده‌ی محلی را قرض بدهید:

use std::thread;

fn main() {
    let mut nums = vec![1, 2, 3, 4];
    let (left, right) = nums.split_at_mut(2);

    thread::scope(|s| {
        s.spawn(|| left.iter_mut().for_each(|x| *x *= 10));
        s.spawn(|| right.iter_mut().for_each(|x| *x += 1));
    }); // اینجا خودکار join می‌شوند

    println!("{nums:?}");
}

Message Passing با Channel

شعار Go: "با اشتراک حافظه ارتباط نگیرید؛ با ارتباط، حافظه را به اشتراک بگذارید." Rust هم channel دارد:

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();   // mpsc: multiple producer, single consumer

    thread::spawn(move || {
        let msg = String::from("سلام از thread");
        tx.send(msg).unwrap();
        // println!("{msg}"); // ✗ مالکیت با send منتقل شد
    });

    let received = rx.recv().unwrap();   // مسدودکننده
    println!("{received}");
}

چند پیام و چند فرستنده

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();
    let tx2 = tx.clone();

    thread::spawn(move || {
        for i in 0..3 {
            tx.send(format!("الف{i}")).unwrap();
        }
    });
    thread::spawn(move || {
        for i in 0..3 {
            tx2.send(format!("ب{i}")).unwrap();
        }
    });

    let mut all: Vec<String> = rx.iter().collect(); // تا وقتی همه‌ی فرستنده‌ها بسته شوند
    all.sort();
    println!("{all:?}");
}

متدها:

  • recv(): منتظر می‌ماند.
  • try_recv(): بدون انتظار، فوراً Result برمی‌گرداند.
  • با پیمایش for x in rx تا بسته شدن کانال خوانده می‌شود.

حافظه‌ی مشترک: Mutex

Mutex (Mutual Exclusion) اجازه می‌دهد در هر لحظه فقط یک thread به داده دسترسی داشته باشد:

use std::sync::Mutex;

fn main() {
    let m = Mutex::new(5);

    {
        let mut num = m.lock().unwrap();   // قفل می‌گیرد
        *num = 6;
    } // اینجا قفل خودکار آزاد می‌شود (Drop)

    println!("{m:?}");
}

در Rust داده داخل Mutex است؛ بدون قفل گرفتن، راهی برای دسترسی به داده وجود ندارد. در C++ می‌شود فراموش کرد قفل بگیرید، ولی اینجا غیرممکن است.

به اشتراک گذاشتن Mutex بین thread ها: Arc

Rc برای چند‌نخی ایمن نیست و کامپایلر اجازه نمی‌دهد. Arc (Atomic Reference Counted) نسخه‌ی thread-safe آن است:

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        }));
    }

    for h in handles {
        h.join().unwrap();
    }

    println!("نتیجه: {}", *counter.lock().unwrap()); // 10
}

Arc<Mutex<T>> معادل Rc<RefCell<T>> در دنیای چند‌نخی است.

RwLock

اگر خواندن زیاد و نوشتن کم است، RwLock چند خواننده‌ی همزمان یا یک نویسنده را مجاز می‌کند:

use std::sync::RwLock;

fn main() {
    let lock = RwLock::new(5);
    {
        let r1 = lock.read().unwrap();
        let r2 = lock.read().unwrap();
        println!("{} {}", *r1, *r2);
    }
    *lock.write().unwrap() += 1;
    println!("{:?}", lock.read().unwrap());
}

Atomic ها

برای شمارنده‌ها و پرچم‌های ساده، Atomic ها از Mutex سریع‌ترند:

use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;
use std::thread;

fn main() {
    let counter = Arc::new(AtomicUsize::new(0));
    let handles: Vec<_> = (0..4)
        .map(|_| {
            let c = Arc::clone(&counter);
            thread::spawn(move || {
                for _ in 0..1000 {
                    c.fetch_add(1, Ordering::SeqCst);
                }
            })
        })
        .collect();

    for h in handles {
        h.join().unwrap();
    }
    println!("{}", counter.load(Ordering::SeqCst)); // 4000
}

Send و Sync

دو trait نشانه (marker) که ایمنی چند‌نخی را تضمین می‌کنند:

  • Send: مالکیت مقدار می‌تواند به thread دیگر منتقل شود.
  • Sync: چند thread می‌توانند همزمان &T داشته باشند.

تقریباً همه‌ی انواع این دو را خودکار دارند. استثناها: Rc (نه Send نه Sync)، RefCell (نه Sync). کامپایلر اگر آن‌ها را به thread بدهید خطا می‌دهد:

use std::rc::Rc;
use std::thread;

fn main() {
    let rc = Rc::new(5);
    thread::spawn(move || {       // ✗ خطا: Rc نمی‌تواند بین thread ها ارسال شود
        println!("{rc}");
    });
}

Deadlock

Rust از data race جلوگیری می‌کند ولی از deadlock نه. اگر دو thread دو قفل را به ترتیب مخالف بگیرند، هر دو برای همیشه منتظر می‌مانند. راه‌حل: همیشه قفل‌ها را به یک ترتیب ثابت بگیرید، قفل را کوتاه نگه دارید و از channel استفاده کنید.

موازی‌سازی داده با Rayon

برای کارهای رایج، crate محبوب rayon پیمایش موازی را با یک تغییر کوچک ممکن می‌کند:

use rayon::prelude::*;

fn main() {
    let sum: u64 = (1..=1_000_000u64).into_par_iter().map(|x| x * x).sum();
    println!("{sum}");
}

تمرین

  1. ۴ thread بسازید که هر کدام مجموع بخشی از یک آرایه‌ی بزرگ را حساب کنند و نتایج را با channel برای main بفرستند.
  2. شمارنده‌ای با Arc<Mutex<i32>> بسازید که ۱۰۰ thread هر کدام ۱۰۰ بار آن را زیاد کنند.
  3. همان کار را با AtomicUsize انجام دهید و سرعت را مقایسه کنید.
  4. سعی کنید Rc را به thread بدهید و خطای کامپایلر را بخوانید.

Pattern Matching به‌طور کامل

Pattern (الگو) نحوی ویژه برای تطبیق با ساختار مقادیر است. تاکنون در match و if let دیده‌اید، اما الگوها در جاهای بیشتری به کار می‌روند.

۱. match

۴. حلقه‌ی for

}

ماکروهای assert

fn main() {

    assert_eq!(2 + 2, 4);

}

Trait Object و برنامه‌نویسی شی‌گرا

آیا Rust شی‌گراست؟ پاسخ: بخشی از ویژگی‌های OOP را دارد، به شکل خودش.

ویژگی OOPدر Rust

کپسوله‌سازیpub و فیلدهای خصوصی
وراثت (Inheritance)ندارد. به‌جایش trait و composition

Rust عمداً وراثت ندارد، چون به coupling زیاد و اشتراک ناخواسته‌ی کد منجر می‌شود. برای اشتراک کد از پیاده‌سازی پیش‌فرض trait یا composition استفاده کنید.

کپسوله‌سازی

pub struct AveragedCollection {
    list: Vec<i32>,
    average: f64,
}

impl AveragedCollection {
    pub fn new() -> Self {
        Self { list: vec![], average: 0.0 }
    }

    pub fn add(&mut self, value: i32) {
        self.list.push(value);
        self.update_average();
    }

    pub fn average(&self) -> f64 {
        self.average
    }

    fn update_average(&mut self) {
        let total: i32 = self.list.iter().sum();
        self.average = total as f64 / self.list.len() as f64;
    }
}

fn main() {
    let mut c = AveragedCollection::new();
    c.add(10);
    c.add(20);
    println!("{}", c.average());
}

فیلدها خصوصی‌اند، پس نمی‌توان average را بدون هماهنگی با list تغییر داد.

Trait Object و چندریختی پویا

مسئله: لیستی از اشیای مختلف که همه یک trait را پیاده می‌کنند.

با generics این ممکن نیست، چون Vec<T> فقط یک نوع T می‌تواند داشته باشد. راه‌حل: dyn Trait:

trait Draw {
    fn draw(&self) -> String;
}

struct Button {
    label: String,
}

struct Slider {
    max: u32,
}

impl Draw for Button {
    fn draw(&self) -> String {
        format!("[ {} ]", self.label)
    }
}

impl Draw for Slider {
    fn draw(&self) -> String {
        format!("|----o---| (0..{})", self.max)
    }
}

struct Screen {
    components: Vec<Box<dyn Draw>>,
}

impl Screen {
    fn render(&self) {
        for c in &self.components {
            println!("{}", c.draw());
        }
    }
}

fn main() {
    let screen = Screen {
        components: vec![
            Box::new(Button { label: String::from("تایید") }),
            Box::new(Slider { max: 100 }),
        ],
    };
    screen.render();
}

Box<dyn Draw> یعنی "pointer به هر نوعی که Draw را پیاده کرده". فراخوانی متد از طریق vtable (جدول توابع مجازی) در زمان اجرا تعیین می‌شود.

نوع قرض‌گرفته هم ممکن است: &dyn Draw.

قاعده‌ی سرانگشتی: اگر مجموعه‌ی نوع‌ها را از قبل می‌دانید و همگن است، generic. اگر کاربر/کتابخانه‌ی دیگر می‌تواند نوع‌های جدید اضافه کند یا مجموعه‌ی ناهمگن لازم دارید، dyn.

وقتی مجموعه‌ی نوع‌ها بسته و معلوم است، enum اغلب بهترین انتخاب است:

enum Shape {
    Circle(f64),
    Rect(f64, f64),
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(r) => 3.14159 * r * r,
            Shape::Rect(w, h) => w * h,

}

Object Safety (dyn-compatible)

همه‌ی trait ها را نمی‌توان dyn کرد. trait فقط وقتی قابل استفاده به‌صورت dyn است که:

  • متدهایش نوع Self را برنگردانند.
  • متدهایش generic نباشند.
#![allow(unused)]
fn main() {
trait Cloner {
    fn duplicate(&self) -> Self;   // برگرداندن Self
}

fn takes(_x: &dyn Cloner) {}      // ✗ خطا: این trait به‌صورت dyn قابل استفاده نیست
}

(دلیل: وقتی نوع واقعی پنهان است، کامپایلر اندازه‌ی Self را نمی‌داند.)

الگوی State با trait object

مثال کلاسیک: یک پست وبلاگ که حالت‌هایی دارد (پیش‌نویس، در انتظار بازبینی، منتشرشده):

trait State {
    fn request_review(self: Box<Self>) -> Box<dyn State>;
    fn approve(self: Box<Self>) -> Box<dyn State>;
    fn content<'a>(&self, _post: &'a Post) -> &'a str {
        ""
    }
}

struct Draft;
struct Pending;
struct Published;

impl State for Draft {
    fn request_review(self: Box<Self>) -> Box<dyn State> { Box::new(Pending) }
    fn approve(self: Box<Self>) -> Box<dyn State> { self }
}
impl State for Pending {
    fn request_review(self: Box<Self>) -> Box<dyn State> { self }
    fn approve(self: Box<Self>) -> Box<dyn State> { Box::new(Published) }
}
impl State for Published {
    fn request_review(self: Box<Self>) -> Box<dyn State> { self }
    fn approve(self: Box<Self>) -> Box<dyn State> { self }
    fn content<'a>(&self, post: &'a Post) -> &'a str {
        &post.content
    }
}

pub struct Post {
    state: Option<Box<dyn State>>,
    content: String,
}

impl Post {
    pub fn new() -> Post {
        Post { state: Some(Box::new(Draft)), content: String::new() }
    }
    pub fn add_text(&mut self, text: &str) {
        self.content.push_str(text);
    }
    pub fn content(&self) -> &str {
        self.state.as_ref().unwrap().content(self)
    }
    pub fn request_review(&mut self) {
        if let Some(s) = self.state.take() {
            self.state = Some(s.request_review());
        }
    }
    pub fn approve(&mut self) {
        if let Some(s) = self.state.take() {
            self.state = Some(s.approve());
        }
    }
}

fn main() {
    let mut post = Post::new();
    post.add_text("امروز راست یاد گرفتم");
    println!("[{}]", post.content());   // خالی
    post.request_review();
    println!("[{}]", post.content());   // خالی
    post.approve();
    println!("[{}]", post.content());   // متن
}

الگوی Type State (روش Rust-محور)

به‌جای حالت در زمان اجرا، حالت را در نوع کدگذاری کنید تا حالت‌های غیرمجاز اصلاً کامپایل نشوند:

pub struct DraftPost {
    content: String,
}

pub struct PendingPost {
    content: String,
}

pub struct PublishedPost {
    content: String,
}

impl DraftPost {
    pub fn new() -> Self {
        DraftPost { content: String::new() }
    }
    pub fn add_text(&mut self, text: &str) {
        self.content.push_str(text);
    }
    pub fn request_review(self) -> PendingPost {
        PendingPost { content: self.content }
    }
}

impl PendingPost {
    pub fn approve(self) -> PublishedPost {
        PublishedPost { content: self.content }
    }
}

impl PublishedPost {
    pub fn content(&self) -> &str {
        &self.content
    }
}

fn main() {
    let mut draft = DraftPost::new();
    draft.add_text("متن پست");
    let pending = draft.request_review();

}

تمرین

  1. trait ی به نام Plugin با متد run(&self) -> String تعریف کنید و Vec<Box<dyn Plugin>> بسازید.
  2. همان مسئله را یک بار با generic و یک بار با enum حل کنید و تفاوت را توضیح بدهید.
  3. با الگوی type state، اتصال شبکه‌ای مدل کنید که حالت‌های Disconnected و Connected دارد و send فقط روی Connected تعریف شده باشد.

فصل بعد: Macro.

Macro

Macro کدی است که کد دیگری تولید می‌کند (metaprogramming). تا اینجا بارها استفاده‌شان کرده‌اید: println!، vec!، format!، assert_eq!، matches!. علامت ! نشان‌دهنده‌ی macro است.

تفاوت macro و تابع

  • تابع تعداد پارامتر ثابت دارد؛ macro می‌تواند تعداد دلخواه بگیرد (println!("a") یا println!("{} {}", a, b)).
  • macro قبل از کامپایل گسترش می‌یابد، پس می‌تواند trait پیاده کند یا نوع بسازد.
  • نوشتنشان سخت‌تر و دیباگشان دشوارتر است.

Rust دو نوع macro دارد:

  1. Declarative با macro_rules!
  2. Procedural: سه شکل derive، attribute-like و function-like

macro_rules!

ساخت یک نسخه‌ی ساده از vec!:

macro_rules! my_vec {
    ( $( $x:expr ),* ) => {
        {
            let mut temp = Vec::new();
            $( temp.push($x); )*
            temp
        }
    };
}

fn main() {
    let v = my_vec![1, 2, 3];
    println!("{v:?}");
}

اجزا:

  • ( ... ) => { ... }: الگو و کد خروجی (مثل match).
  • $x:expr: ضبط یک expression و نام‌گذاری آن $x.
  • $( ... ),*: تکرار صفر یا چند بار با جداکننده‌ی ,.
  • $( temp.push($x); )* در خروجی، به‌ازای هر تکرار کد را تولید می‌کند.

Procedural Macro

این macro ها یک تابع Rust هستند که جریان token ها را می‌گیرند و جریان جدید برمی‌گردانند. باید در crate جداگانه با proc-macro = true نوشته شوند (و معمولاً از crate های syn و quote کمک می‌گیرند).

۱. Derive Macro

همان #[derive(Debug)] که می‌شناسید. crate ی مثل serde با #[derive(Serialize, Deserialize)] کد تبدیل به JSON را تولید می‌کند:

use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug)]
struct User {
    name: String,
    age: u32,
}

۲. Attribute-like

#[route(GET, "/")]
fn index() {}

۳. Function-like

let sql = sql!(SELECT * FROM posts WHERE id = 1);

اسکلت یک derive macro (کد به‌خاطر نیاز به crate مستقل فقط برای مشاهده است):

use proc_macro::TokenStream;
use quote::quote;
use syn;

#[proc_macro_derive(HelloMacro)]
pub fn hello_macro_derive(input: TokenStream) -> TokenStream {
    let ast: syn::DeriveInput = syn::parse(input).unwrap();
    let name = &ast.ident;
    let gen = quote! {
        impl HelloMacro for #name {
            fn hello_macro() {
                println!("سلام! من {} هستم", stringify!(#name));
            }
        }
    };
    gen.into()
}

کی macro بنویسیم؟

  • وقتی تابع و generic کافی نیست: تعداد آرگومان متغیر، تولید کد تکراری، DSL.
  • ابتدا تابع یا generic را امتحان کنید. macro آخرین گزینه است.
  • ابزار cargo expand (باید نصب شود) خروجی گسترش‌یافته‌ی macro را نشان می‌دهد و برای یادگیری و دیباگ عالی است.

تمرین

  1. macro ی square!(x) بنویسید که مربع یک expression را حساب کند.
  2. macro ی min! مانند maximum! بنویسید.
  3. macro ی بنویسید که برای یک struct با لیست فیلدها، تابع new تولید کند.

Async و await

برنامه‌نویسی async برای کارهایی است که بیشتر وقتشان صرف انتظار می‌شود: درخواست شبکه، خواندن از دیسک، پایگاه‌داده. به‌جای اینکه برای هر کار یک thread سنگین بسازیم، هزاران کار را روی تعداد کمی thread مدیریت می‌کنیم.

Future

در Rust، تابع async فوراً اجرا نمی‌شود. یک Future برمی‌گرداند؛ مقداری که "در آینده" آماده می‌شود. Future ها تنبل هستند و تا await یا poll نشوند کاری نمی‌کنند:

async fn compute() -> u32 {
    42
}

fn main() {
    let _future = compute();   // هنوز هیچ کاری نشده
    println!("future ساخته شد ولی اجرا نشد");
}

trait ی ساده‌شده‌ی Future:

trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

مقدار Poll یا Ready(مقدار) یا Pending است.

await

داخل تابع async با .await منتظر Future دیگر می‌مانیم، بدون اینکه thread را مسدود کنیم:

async fn fetch_user(id: u32) -> String {
    format!("user-{id}")
}

async fn show() {
    let user = fetch_user(1).await;
    println!("{user}");
}

Runtime

کتابخانه‌ی استاندارد runtime ندارد؛ یعنی چیزی که Future ها را اجرا و زمان‌بندی کند در خود زبان نیست. باید یک crate انتخاب کنید. محبوب‌ترین: Tokio. گزینه‌های دیگر: async-std و smol.

use tokio::time::sleep;

    println!("شروع");
    sleep(Duration::from_millis(500)).await;
    println!("بعد از نیم ثانیه");
}

async fn main() {
    // پشت سر هم: ۳۰۰ + ۲۰۰ میلی‌ثانیه
    let a = task("الف", 300).await;
    let b = task("ب", 200).await;
    println!("{a} / {b}");

    // همزمان: فقط ۳۰۰ میلی‌ثانیه (طولانی‌ترین)
    let (a, b) = tokio::join!(task("الف", 300), task("ب", 200));
    println!("{a} / {b}");

    // ساخت taskهای مستقل (مثل thread سبک)
    let h1 = tokio::spawn(async { task("ج", 100).await });
    let h2 = tokio::spawn(async { task("د", 100).await });
    println!("{} / {}", h1.await.unwrap(), h2.await.unwrap());
}

Timeout و انتخاب اولین نتیجه

use std::time::Duration;
use tokio::time::{sleep, timeout};

#[tokio::main]
async fn main() {
    let result = timeout(Duration::from_millis(100), sleep(Duration::from_secs(5))).await;
    println!("{}", result.is_err());   // true: زمان تمام شد

    tokio::select! {
        _ = sleep(Duration::from_millis(50)) => println!("اولی برنده شد"),
        _ = sleep(Duration::from_millis(500)) => println!("دومی برنده شد"),
    }
}

نکات مهم

  • کار سنگین CPU را داخل async انجام ندهید. thread ی که runtime روی آن است مسدود می‌شود. از tokio::task::spawn_blocking استفاده کنید.
  • Mutex ی استاندارد را هنگام .await نگه ندارید. از tokio::sync::Mutex استفاده کنید.
  • Future ها باید Send باشند تا بین thread ها جابه‌جا شوند. Rc داخل async معمولاً مشکل می‌سازد.
  • Cancellation: با رها کردن (drop) یک Future، اجرای آن متوقف می‌شود. این قدرتمند است ولی باید حواستان به حالت میانی باشد.
  • هر دو سبک (thread و async) را می‌شود ترکیب کرد.

فصل بعد: Unsafe Rust.

Unsafe Rust

تمام آنچه تاکنون نوشتید Safe Rust بود؛ کامپایلر ایمنی حافظه را تضمین می‌کند. اما گاهی لازم است از این قید بیرون بیایید:

  • کار با سخت‌افزار و سیستم‌عامل
  • فراخوانی کد C
  • بهینه‌سازی‌های خاص
  • پیاده‌سازی ساختارهایی که کامپایلر نمی‌تواند درستی‌شان را ثابت کند

برای این منظور بلوک unsafe وجود دارد.

مهم: unsafe بررسی‌های ایمنی را خاموش نمی‌کند؛ فقط به شما اجازه می‌دهد پنج کار اضافی انجام دهید. مسئولیت درستی آن‌ها با شماست.

پنج توانایی unsafe

  1. دسترسی به مقدار raw pointer (dereference)
  2. فراخوانی تابع یا متد unsafe
  3. دسترسی یا تغییر static mut
  4. پیاده‌سازی unsafe trait
  5. دسترسی به فیلد union

Raw Pointer

دو نوع: *const T و *mut T. تفاوت با reference:

  • قوانین borrowing را رعایت نمی‌کنند (می‌توانند همزمان *mut و *const به یک جا باشند).
  • ممکن است null یا نامعتبر باشند.
  • خودکار آزاد نمی‌شوند.

ساختن raw pointer ایمن است، فقط خواندن/نوشتن از طریق آن unsafe است:

fn main() {
    let mut num = 5;

    let r1 = &raw const num;
    let r2 = &raw mut num;

    unsafe {
        *r2 += 1;
        println!("r1 = {}", *r1);
        println!("r2 = {}", *r2);
    }
}

تابع unsafe

unsafe fn dangerous(p: *const i32) -> i32 {
    unsafe { *p }
}

fn main() {
    let x = 42;
    let v = unsafe { dangerous(&x) };
    println!("{v}");
}

ساخت انتزاع ایمن روی کد unsafe

الگوی اصلی: کد unsafe را کوچک نگه دارید و پشت یک API ایمن پنهان کنید. مثلاً split_at_mut در کتابخانه‌ی استاندارد دو slice قابل‌تغییر و جدا از یک slice می‌دهد، کاری که borrow checker به‌تنهایی نمی‌تواند ثابتش کند:

use std::slice;

fn my_split_at_mut(values: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
    let len = values.len();
    let ptr = values.as_mut_ptr();

    assert!(mid <= len);

    unsafe {
        (
            slice::from_raw_parts_mut(ptr, mid),
            slice::from_raw_parts_mut(ptr.add(mid), len - mid),
        )
    }
}

fn main() {
    let mut v = vec![1, 2, 3, 4, 5, 6];
    let (a, b) = my_split_at_mut(&mut v, 3);
    a[0] = 100;
    b[0] = 200;
    println!("{v:?}");
}

مسئولیت درستی با ماست: assert! تضمین می‌کند محدوده معتبر است و دو slice همپوشانی ندارند.

گام ۳: Config

آرگومان‌های خط فرمان را در struct جمع می‌کنیم. تابع build به‌جای panic، Result برمی‌گرداند:

use std::env;
use std::error::Error;
use std::fs;

pub struct Config {
    pub query: String,
    pub file_path: String,
    pub ignore_case: bool,
}

impl Config {
    pub fn build(mut args: impl Iterator<Item = String>) -> Result<Config, &'static str> {
        args.next(); // نام برنامه را رد می‌کنیم

        let query = match args.next() {
            Some(arg) => arg,
            None => return Err("عبارت جستجو داده نشده است"),
        };

        let file_path = match args.next() {
            Some(arg) => arg,
            None => return Err("مسیر فایل داده نشده است"),
        };

        let ignore_case = env::var("IGNORE_CASE").is_ok();

        Ok(Config { query, file_path, ignore_case })
    }
}

نکات:

  • impl Iterator<Item = String> یعنی هر iterator ی از String ها؛ در main همان env::args() است و در تست می‌توانیم لیست دلخواه بدهیم.
  • env::var("IGNORE_CASE").is_ok() بررسی می‌کند متغیر محیطی تنظیم شده یا نه.

گام ۴: تابع run

pub fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(&config.file_path)?;

    let results = if config.ignore_case {
        search_case_insensitive(&config.query, &contents)
    } else {
        search(&config.query, &contents)
    };

    for line in results {
        println!("{line}");
    }

    Ok(())
}
  • ? خطای خواندن فایل را به فراخواننده برمی‌گرداند.

گام ۵: توابع جستجو (با lifetime)

خط‌های برگشتی از متن ورودی هستند، پس lifetime ی خروجی به contents وصل است، نه query:

pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    contents
        .lines()
        .filter(|line| line.contains(query))
        .collect()
}

pub fn search_case_insensitive<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let query = query.to_lowercase();
    contents
        .lines()
        .filter(|line| line.to_lowercase().contains(&query))
        .collect()
}

این‌جا از iterator و closure استفاده کردیم: نسبت به حلقه‌ی دستی کوتاه‌تر و به همان اندازه سریع است.

پاسخ تمرین‌ها (بخش ۱): فصل‌های ۲ تا ۱۲

این صفحه پاسخ تمرین‌های انتهای فصل‌های ۲ تا ۱۲ را دارد. پیشنهاد جدی: اول خودتان تمرین را حل کنید، حتی اگر ناقص بود، و بعد پاسخ را ببینید. یادگیری Rust بیشتر از هر چیز از جنگیدن با کامپایلر می‌آید، نه از خواندن راه‌حل آماده.

چند نکته درباره‌ی پاسخ‌ها:

  • هر پاسخ فقط یک راه‌حل ممکن است. اگر راه‌حل شما متفاوت اما درست بود، اشکالی ندارد.
  • همه‌ی بلوک‌های rust این صفحه با mdbook test کامپایل و اجرا می‌شوند. جایی که از assert! و assert_eq! استفاده شده، یعنی نتیجه واقعاً بررسی شده است.
  • تمرین‌هایی که ذاتاً «خطای کامپایلر را بخوانید» هستند با برچسب compile_fail آمده‌اند: این بلوک‌ها عمداً کامپایل نمی‌شوند و mdBook همین را تأیید می‌کند.
  • فصل ۱ (نصب) تمرین ندارد.

فصل ۳: متغیرها و تغییرپذیری

تمرین ۱. تغییر دادن متغیر immutable خطای E0384 می‌دهد:

fn main() {
    let x = 5;
    println!("x = {x}");
    x = 6; // error[E0384]: cannot assign twice to immutable variable `x`
    println!("x = {x}");
}

پیام کامپایلر می‌گوید «نمی‌توان دو بار به متغیر immutable مقدار داد» و پیشنهاد می‌کند let mut x بنویسید. بخوانید: کامپایلر Rust معمولاً راه‌حل را هم می‌گوید.

تمرین ۲. با mut:

fn main() {
    let mut x = 5;
    x = 6;
    x += 1;
    assert_eq!(x, 7);
}

تمرین ۳. const باید نوع صریح داشته باشد و نامش به‌صورت SCREAMING_SNAKE_CASE است:

const PI: f64 = 3.14159;

fn main() {
    let radius = 5.0;
    let area = PI * radius * radius;
    println!("مساحت: {area}");
    assert!((area - 78.53975).abs() < 1e-9);
}

نکته: در کد واقعی std::f64::consts::PI دقیق‌تر است و نیازی به تعریف ثابت خودتان نیست. اینجا فقط برای تمرین const خواسته شده بود.

تمرین ۴. shadowing اجازه می‌دهد با همان نام، نوع را عوض کنید (برخلاف mut که نوع را ثابت نگه می‌دارد):

fn main() {
    let value = "42";
    let value = value.parse::<i32>().unwrap(); // اینجا مقدار ثابت و مطمئن است
    assert_eq!(value + 1, 43);
}

هشدار: unwrap اینجا فقط چون رشته‌ی ثابت "42" است قابل قبول است. برای ورودی کاربر از match یا ? استفاده کنید (فصل ۱۴).

fn mean(v: &[i32]) -> Option<f64> {
    if v.is_empty() {
        return None;
    }
    let sum: i64 = v.iter().map(|&x| i64::from(x)).sum();
    Some(sum as f64 / v.len() as f64)
}

fn median(v: &[i32]) -> Option<f64> {
    if v.is_empty() {
        return None;
    }
    let mut sorted = v.to_vec(); // کپی می‌کنیم تا ورودی را تغییر ندهیم
    sorted.sort_unstable();
    let mid = sorted.len() / 2;
    if sorted.len() % 2 == 1 {
        Some(f64::from(sorted[mid]))
    } else {
        Some((f64::from(sorted[mid - 1]) + f64::from(sorted[mid])) / 2.0)
    }
}

    assert_eq!(mean(&data), Some(4.5));
    assert_eq!(median(&data), Some(4.0)); // (3 + 5) / 2
    assert_eq!(median(&[7, 1, 3]), Some(3.0));
    assert_eq!(mean(&[]), None);
}

تمرین ۲. Pig Latin. قاعده‌ی تمرین: کلمه‌ای که با بی‌صدا شروع شود، حرف اولش به انتها می‌رود و ay می‌گیرد. برای کلمه‌ی شروع‌شده با واکه (چیزی که تمرین نگفته) قرارداد معمول «hay به انتها» را می‌گیریم. حواسمان به UTF-8 است: به‌جای برش بایتی، از chars() استفاده می‌کنیم.

fn pig_latin_word(word: &str) -> String {
    let mut chars = word.chars();
    let Some(first) = chars.next() else {
        return String::new();
    };
    if "aeiouAEIOU".contains(first) {
        format!("{word}hay")
    } else {
        format!("{}{first}ay", chars.as_str())
    }
}

fn pig_latin(text: &str) -> String {
    text.split_whitespace()
        .map(pig_latin_word)
        .collect::<Vec<_>>()
        .join(" ")
}

fn main() {
    assert_eq!(pig_latin_word("first"), "irstfay");
    assert_eq!(pig_latin_word("apple"), "applehay");
    assert_eq!(pig_latin("hello world"), "ellohay orldway");
    assert_eq!(pig_latin_word(""), "");
}

chars.as_str() باقی‌مانده‌ی iterator را به‌صورت &str می‌دهد (بدون allocate اضافه).

تمرین ۳. سیستم کارمندان. HashMap<String, Vec<String>>؛ با entry().or_default() اضافه می‌کنیم و برای چاپ مرتب، هم کلیدها و هم هر لیست را مرتب می‌کنیم (چون ترتیب HashMap تعریف‌نشده است). از BTreeMap هم می‌شد استفاده کرد تا کلیدها خودکار مرتب باشند، اما خود تمرین HashMap خواسته:

use std::collections::HashMap;

#[derive(Default)]
struct Company {
    departments: HashMap<String, Vec<String>>,
}

impl Company {
    fn add(&mut self, department: &str, person: &str) {
        self.departments
            .entry(department.to_string())
            .or_default()
            .push(person.to_string());
    }

    /// فرمان‌هایی مانند "Add Sally to Engineering" را اجرا می‌کند.
    fn run_command(&mut self, cmd: &str) -> bool {
        let words: Vec<&str> = cmd.split_whitespace().collect();
        match words.as_slice() {
            ["Add", person, "to", department] => {
                self.add(department, person);
                true
            }
            _ => false,
        }
    }

    fn sorted_people(&self, department: &str) -> Vec<&str> {
        let mut people: Vec<&str> = self
            .departments
            .get(department)
            .map(|v| v.iter().map(String::as_str).collect())
            .unwrap_or_default();
        people.sort();
        people
    }

    fn print_all(&self) {
        let mut names: Vec<&String> = self.departments.keys().collect();
        names.sort();
        for dept in names {
            println!("{dept}: {}", self.sorted_people(dept).join(", "));
        }
    }
}

fn main() {
    let mut company = Company::default();
    assert!(company.run_command("Add Sally to Engineering"));
    assert!(company.run_command("Add Amir to Engineering"));
    assert!(company.run_command("Add Reza to Sales"));
    assert!(!company.run_command("Remove Reza"));

    assert_eq!(company.sorted_people("Engineering"), ["Amir", "Sally"]);
    assert_eq!(company.sorted_people("Sales"), ["Reza"]);
    assert!(company.sorted_people("HR").is_empty());
    company.print_all();
}

الگوی slice در match words.as_slice() در فصل ۲۲ کامل توضیح داده شده است.

تمرین ۴. شمارش تکرار هر حرف. اینجا هم «حرف» را char در نظر می‌گیریم. BTreeMap برای خروجی مرتب و قابل پیش‌بینی انتخاب شد:

use std::collections::BTreeMap;

fn char_counts(s: &str) -> BTreeMap<char, usize> {
    let mut counts = BTreeMap::new();
    for c in s.chars().filter(|c| !c.is_whitespace()) {
        *counts.entry(c).or_insert(0) += 1;
    }
    counts
}

fn main() {
    let counts = char_counts("hello world");
    assert_eq!(counts[&'l'], 3);
    assert_eq!(counts[&'o'], 2);
    assert_eq!(counts.get(&'z'), None);

    let fa = char_counts("سلام");
    assert_eq!(fa[&'س'], 1);
    assert_eq!(fa[&'ا'], 1);
    for (c, n) in &counts {
        println!("{c}: {n}");
    }
}

اگر به‌جای BTreeMap از HashMap استفاده کنید، منطق همان است ولی ترتیب چاپ هر بار ممکن است فرق کند.

جمع‌بندی: اگر در حل یک تمرین گیر کردید، به جای نگاه کردن به پاسخ، پیام کامپایلر را کلمه‌به‌کلمه بخوانید و به فصل مربوط برگردید. پاسخ تمرین‌های فصل‌های ۱۳ تا ۲۷ در پاسخ تمرین‌ها (بخش ۲) است.
